# 🔧 Pro Kisan — मंडी API का सुधार (सर्वर पर लगाने की विधि)

> बनी: 3 अगस्त 2026
>
> ## ✅ यह सब **सर्वर पर लग चुका है** (3 अगस्त, रात 1:15 IST)
>
> यह फ़ाइल अब सिर्फ़ **रिकॉर्ड** के लिए है — क्या-क्या बदला और क्यों।
> दोबारा लगाने की ज़रूरत नहीं। आगे कभी सर्वर बदलना पड़े तो यही विधि काम आएगी।

## 🎯 एक वाक्य में

सर्वर पर मंडी का पूरा सिस्टम **पहले से बना और चल रहा है** (MySQL + cron sync)।
उसे दोबारा नहीं बनाना।

पर सर्वर पर जो चल रहा है वह **पुराना version है** — दो ज़रूरी सुधार उसमें कभी
चढ़े ही नहीं। यह folder वही सुधार लेकर आया है, साथ में तीन नई चीज़ें।

**कुछ भी मिटाना नहीं है। फ़ाइलें बदलनी हैं।**

---

## 🔴 सर्वर पर जो चल रहा है, उसमें दो बग हैं

### बग 1 — `date` भेजा ही नहीं जाता

सर्वर वाली `api/mandi.php` डेटाबेस से `arrival_date` **पढ़ती तो है**, पर
JSON में **डालती ही नहीं**:

```php
$out[] = [
    'state' => ..., 'commodity' => ..., 'msp' => ...,
    // ← 'date' यहाँ है ही नहीं
];
```

**नतीजा:** ऐप `item['date']` पढ़ता है, हमेशा `null` मिलता है, इसलिए
**"📅 भाव इस तारीख़ तक के" वाली पट्टी कभी नहीं दिखती।** किसान को पता ही
नहीं चलता कि भाव आज का है या तीन दिन पुराना — और उसी पर फ़सल लेकर मंडी
चला जाता है।

### बग 2 — राज्य वाला बचाव (एहतियात, अभी गड़बड़ नहीं मिली)

पुरानी `cron/mandi_sync.php` हर पंक्ति पर **वही राज्य चिपका देती थी जो उसने
API से माँगा था**। data.gov.in का `filters[state]` हमेशा भरोसेमंद नहीं —
23 जुलाई की जाँच में *"Andaman and Nicobar" माँगने पर 110 पंक्तियाँ आईं
जिनमें 93 जम्मू-कश्मीर की थीं*।

**पर 3 अगस्त 2026 को डेटाबेस जाँचने पर वह गड़बड़ी नहीं मिली।** पक्का टेस्ट —
*कोई ज़िला दो राज्यों में तो नहीं?* — में सिर्फ़ 3 नाम आए, और तीनों सचमुच
दो राज्यों में हैं (Bilaspur, Hamirpur, Pratapgarh)। कश्मीर का Baramulla
जम्मू-कश्मीर में ही है। यानी **23 जुलाई को `fix_wrong_states.sql` चलाया
जा चुका था और तब से डेटा साफ़ है**।

नई sync फिर भी **हर पंक्ति का अपना राज्य पढ़ती है** — यह एहतियात है, ताकि
data.gov.in दोबारा गड़बड़ करे तो असर न पड़े।

> ⚠️ **`sql/fix_wrong_states.sql` अभी मत चलाइए।** वह TRUNCATE करता है और कई
> दिन का भाव-इतिहास मिटा देता है। फ़ाइल के ऊपर चेतावनी और जाँचने की क्वेरी
> लिखी है — पहले वह चलाइए।

### 🔴 बग 2 (असली) — समय 5:30 घंटे पीछे दिखता था

MySQL `updated_at` को **UTC में** सहेजता है (सर्वर UTC पर है)। API उसे IST
मानकर पढ़ रहा था, इसलिए सुबह 6:43 का sync ऐप में **"रात 1:13"** दिखता।
अब `strtotime($r['updated_at'] . ' UTC')` से सही बदलाव होता है।

### 🔴 बग 3 (असली) — ज़िले अंग्रेज़ी में, ऐप हिंदी से छाँटता था

सर्वर ज़िला अंग्रेज़ी में सहेजता है ("Salem"), ऐप की सूची हिंदी में थी
("सलेम") — इसलिए किसान अपना ज़िला चुनता और **सूची ख़ाली** मिलती।

data.gov.in **519 अलग वर्तनियाँ** भेजता है (`Mau(Maunathbhanjan)`,
`Alluri Sitharama Raju`), ऐप के पास सिर्फ़ 177 थे। सर्वर पर अनुवाद करने से
आधे बदलते और आधे नहीं, और एक ही ज़िला दो नामों से दिखता। इसलिए:

- **सर्वर** ज़िला एक ही रूप में सहेजता है (जैसा स्रोत से आया)
- **ऐप** की ज़िला-सूची अब **असली भाव से बनती है** — छँटाई कभी ख़ाली नहीं जाती
- **ऐप** जिन 177 का हिंदी नाम जानता है वहाँ हिंदी दिखाता है

## 🆕 और तीन नई चीज़ें

| क्या | क्यों |
|---|---|
| `fetchedAt` | "भाव कब उठाया" — तारीख़ से अलग बात, दोनों दिखाना ज़रूरी |
| समय का नाप | cron का सही समय अंदाज़े से नहीं, **नापकर** तय हो |
| `days`/`limit` बढ़े | 3 दिन और 500 पंक्तियाँ बहुत कम पड़ रही थीं |

**`date` और `fetchedAt` दो अलग बातें हैं:**

| | मतलब |
|---|---|
| `date` | मंडी में सौदा **किस दिन** हुआ |
| `fetchedAt` | हमारे सर्वर ने वह भाव **कब उठाया** |

ऐप दोनों दिखाता है:

```
📅 भाव इस तारीख़ तक के: 2 अग (कल)
🕒 ऐप में आए: 3 अग, शाम 6:04
```

सिर्फ़ उठाने का समय दिखे तो 3 दिन पुराना भाव ताज़ा लगेगा। सिर्फ़ तारीख़ दिखे
तो पता न चले कि जानकारी कितनी बासी है।

## 📂 इस folder में क्या है

```
SERVER_UPDATE/
├── README.md                   यही फ़ाइल — सुधार की विधि
├── CLEANUP.md                  🧹 पुरानी/दोहरी फ़ाइलें हटाने की विधि
├── api/
│   └── mandi.php               ✅ बदलिए — date + fetchedAt + IST + days/limit
├── cron/
│   ├── mandi_sync.php          ✅ बदलिए — राज्य वाला बग-फ़िक्स + समय का नाप
│   └── when_updates.php        🆕 नई — "कब अपडेट आता है" नापकर बताती है
├── includes/
│   └── mandi_map.php           ✅ बदलिए (या मिलाइए) — राज्य/फ़सल का पूरा नक्शा
└── sql/
    ├── add_sync_log.sql        🆕 नया टेबल — sync का हिसाब
    └── fix_wrong_states.sql    🔧 एक बार — ग़लत राज्य वाली पुरानी पंक्तियाँ साफ़
```

## 🔢 काम का सही क्रम

1. **पहले `CLEANUP.md`** — सर्वर पर असल में क्या-क्या पड़ा है वह पता कीजिए
   और नक़ल (backup) बना लीजिए
2. **फिर यह README** — सुधार लगाइए
3. **एक हफ़्ते बाद** — `php cron/when_updates.php` चलाकर cron का समय कसिए

> ⚠️ **सफ़ाई पहले क्यों:** सर्वर पर दो लगभग एक जैसे folder हो सकते हैं। पहले
> तय कीजिए कि ऐप असल में **किस folder** को पूछता है — वरना सुधार ग़लत जगह
> लग जाएगा और लगेगा कि "कुछ बदला ही नहीं"।

## 🔧 लगाने के 7 क़दम

### क़दम 1 — पुरानी फ़ाइलों की नक़ल

```bash
cd /var/www/prokisan_api
mkdir -p /root/prokisan_backup
tar czf /root/prokisan_backup/before_update_$(date +%F).tar.gz .
mysqldump -u prokisan_user -p pro_kisan_db > /root/prokisan_backup/db_$(date +%F).sql
ls -lh /root/prokisan_backup/
```

**दोनों फ़ाइलें दिखनी चाहिए और आकार शून्य नहीं होना चाहिए।**

### क़दम 2 — नया टेबल

```bash
mysql -u prokisan_user -p pro_kisan_db < sql/add_sync_log.sql
```

*(यह टेबल न भी बने तो कुछ नहीं टूटेगा — बस समय का नाप नहीं होगा।)*

### क़दम 3 — तीन फ़ाइलें बदलिए

```
api/mandi.php          →  /var/www/prokisan_api/api/mandi.php
cron/mandi_sync.php    →  /var/www/prokisan_api/cron/mandi_sync.php
includes/mandi_map.php →  /var/www/prokisan_api/includes/mandi_map.php
cron/when_updates.php  →  /var/www/prokisan_api/cron/when_updates.php   (नई)
```

`api/mandi.php` में ये बदलाव हैं:

| क्या बदला | पहले | अब |
|---|---|---|
| `date` | भेजा ही नहीं जाता था | ✅ भेजा जाता है |
| `fetchedAt` | था ही नहीं | ✅ `updated_at` से |
| समय-क्षेत्र | सर्वर का (शायद UTC) | ✅ **IST** |
| `days` डिफ़ॉल्ट | 3 | **7** |
| `limit` डिफ़ॉल्ट | 500 | **2000** |

> **`days` 3 से 7 क्यों:** कई मंडियाँ हफ़्ते में 2-3 दिन ही खुलती हैं, और
> data.gov.in भी देर से भरता है। 3 दिन में कई ज़िले ख़ाली दिख रहे थे।
>
> **`limit` 500 से 2000 क्यों:** 20 राज्य × 35 फ़सल में 500 पंक्तियाँ बहुत
> कम पड़ती हैं — किसान अपना ज़िला चुनता और सूची ख़ाली मिलती।

### क़दम 4 — ⚠️ API key बाहर निकालिए (यह ज़रूर कीजिए)

`cron/mandi_sync.php` में `DEFAULT_KEY` के आगे **असली data.gov.in key साफ़
लिखी हुई है**। फ़ाइल ख़ुद कहती है कि यह ग़लत तरीक़ा है।

```bash
crontab -e
```

सबसे ऊपर:
```cron
DATA_GOV_KEY=आपकी-असली-key
```

फिर कोड में:
```php
const DEFAULT_KEY = '';   // key ab crontab me hai
```

**यह folder किसी और को भेजने से पहले ज़रूर कीजिए।**

### क़दम 5 — ग़लत राज्य वाली पुरानी पंक्तियाँ साफ़ कीजिए

नई `mandi_sync.php` आगे से सही राज्य सहेजेगी, पर **टेबल में पड़ी पुरानी ग़लत
पंक्तियाँ अपने आप नहीं हटेंगी** (UNIQUE key में राज्य भी है, इसलिए सही
पंक्ति *नई* बनेगी और ग़लत वाली पड़ी रहेगी)।

```bash
# पहले देखिए कितना गड़बड़ है
mysql -u prokisan_user -p pro_kisan_db -e \
  "SELECT state, COUNT(*) FROM mandi_rates GROUP BY state ORDER BY 2 DESC;"

# फिर साफ़ कीजिए
mysql -u prokisan_user -p pro_kisan_db < sql/fix_wrong_states.sql

# और तुरंत दोबारा भरिए
php /var/www/prokisan_api/cron/mandi_sync.php
```

> यह `TRUNCATE` करता है। **डरिए मत** — भाव रोज़ बदलते हैं, कुछ खोने का डर
> नहीं। sync 2 मिनट में पूरा डेटा वापस ले आएगा, इस बार सही राज्यों के साथ।

### क़दम 6 — cron का समय

```bash
crontab -e
```

पुरानी पंक्ति (`0 6,18 * * *`) हटाकर ये चार रखिए:

```cron
DATA_GOV_KEY=आपकी-असली-key

# Pro Kisan — मंडी भाव (IST मानकर; सर्वर UTC पर हो तो 5:30 घंटे घटाइए)
30 13 * * *  /usr/bin/php /var/www/prokisan_api/cron/mandi_sync.php >> /var/log/prokisan_mandi.log 2>&1
0  18 * * *  /usr/bin/php /var/www/prokisan_api/cron/mandi_sync.php >> /var/log/prokisan_mandi.log 2>&1
30 21 * * *  /usr/bin/php /var/www/prokisan_api/cron/mandi_sync.php >> /var/log/prokisan_mandi.log 2>&1
0  7  * * *  /usr/bin/php /var/www/prokisan_api/cron/mandi_sync.php >> /var/log/prokisan_mandi.log 2>&1
```

| समय (IST) | क्यों |
|---|---|
| 13:30 | सुबह की नीलामी के आँकड़े चढ़ चुके होते हैं |
| **18:00** | दिन भर का ज़्यादातर डेटा — **सबसे ज़्यादा उम्मीद यहीं** |
| 21:30 | देर से भरने वाली मंडियाँ |
| 07:00 | कल का जो छूटा |

### क़दम 7 — जाँच लीजिए

```bash
# sync एक बार हाथ से
php /var/www/prokisan_api/cron/mandi_sync.php

# JSON में date और fetchedAt आ रहे हैं?
curl -sk "https://localhost/prokisan_api/api/mandi.php?limit=1" | python3 -m json.tool
```

ऐसा दिखना चाहिए:

```json
[
  {
    "state": "उत्तर प्रदेश",
    "district": "वाराणसी",
    "mandi": "वाराणसी",
    "commodity": "गेहूं",
    "minPrice": 2200,
    "maxPrice": 2350,
    "modalPrice": 2290,
    "msp": 2275,
    "date": "2026-08-02",
    "fetchedAt": "2026-08-03 18:04"
  }
]
```

```bash
# कितने भाव, कौन-सी तारीख़?
curl -sk "https://localhost/prokisan_api/api/mandi.php" | python3 -c "import sys,json;d=json.load(sys.stdin);print(len(d),'bhaav');print('sabse nai tareekh:',max(x['date'] for x in d))"

# राज्यों के नाम सही हैं?
mysql -u prokisan_user -p pro_kisan_db -e "SELECT state, COUNT(*) FROM mandi_rates GROUP BY state ORDER BY 2 DESC LIMIT 10;"

# log भर रहा है?
mysql -u prokisan_user -p pro_kisan_db -e "SELECT * FROM mandi_sync_log ORDER BY id DESC LIMIT 5;"
```

फिर **ऐप खोलिए → खेती → मंडी भाव।** ऊपर दो पंक्तियाँ दिखनी चाहिए, और
नारंगी चेतावनी *("ये अनुमानित भाव हैं")* **हट जानी चाहिए**।

## ⏰ एक हफ़्ते बाद — यह ज़रूर चलाइए

```bash
php /var/www/prokisan_api/cron/when_updates.php
```

**data.gov.in कहीं नहीं बताता कि वह दिन में किस समय ताज़ा होता है।** मंडी के
APMC कर्मचारी दिन भर आँकड़े भरते रहते हैं। इसलिए हर sync पर `mandi_sync_log`
में लिख दिया जाता है कि *किस समय चलाने पर कौन-सी तारीख़ का भाव मिला*।

यह script वही पढ़कर बता देगा:

```
किस समय चलाने पर कितना ताज़ा भाव मिला
════════════════════════════════════════════════════════════════
समय       बार     ताज़गी (दिन)    पंक्तियाँ   मंडी
────────────────────────────────────────────────────────────────
07:00     7       1.0             2610        395
13:00     7       0.9             2733        402
18:00     7       0.2             2891        438
21:00     7       0.2             2903        441
════════════════════════════════════════════════════════════════

सबसे अच्छा समय: 18:00 — भाव औसतन 0.2 दिन पुराना, 438 मंडी
```

फिर बेकार के चक्कर हटाकर सिर्फ़ 18:00 और 21:30 रख दीजिए।
**अंदाज़े से नहीं, अपने सर्वर पर नापकर।**

| दिक्कत | वजह और इलाज |
|---|---|
| ऐप में अब भी नारंगी चेतावनी | API ख़ाली `[]` दे रहा है → `php cron/mandi_sync.php` चलाकर संदेश पढ़िए |
| तारीख़ की पट्टी अब भी नहीं दिखती | `api/mandi.php` बदली नहीं गई |
| `fetchedAt` ख़ाली | टेबल में `updated_at` खाना नहीं → `DESCRIBE mandi_rates;` |
| समय 5:30 घंटे पीछे | `date_default_timezone_set('Asia/Kolkata')` जुड़ा नहीं |
| राज्य चुनने पर ख़ाली | पुरानी ग़लत पंक्तियाँ पड़ी हैं → क़दम 5 कीजिए |
| `mandi_sync_log` की शिकायत | टेबल नहीं बना → `sql/add_sync_log.sql` चलाइए। *(sync फिर भी नहीं टूटेगा)* |
| SSL की शिकायत | ऐप में **certificate pinning** है (`lib/services/ssl_pinning.dart`)। सर्टिफ़िकेट बदला हो तो ऐप में नया SHA-256 fingerprint डालना पड़ेगा |
